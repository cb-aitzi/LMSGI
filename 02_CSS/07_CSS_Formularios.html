¿Para qué sirve un formulario?

Un formulario web permite a los usuarios enviar información a un sitio web, de forma rápida y organizada.

Recoger datos

Datos personales, correos electrónicos, opiniones...

Comunicación

Contactar con una empresa, solicitar información, enviar consultas.

Transacciones

Compras online: datos del pedido, el pago, la entrega.

Registro e inscripción

Crear una cuenta, inscribirse en cursos o eventos, iniciar sesión.

HTML5 mejoró mucho los formularios con nuevos tipos de campo y atributos. Puedes comprobar la compatibilidad de cada característica en caniuse.com o en MDN.

Partes de un formulario y cómo funciona

  • Campos de entrada: donde el usuario escribe o selecciona información: texto, correo, fecha, número, contraseña, listas desplegables, casillas de verificación...
  • Botones: el principal es Enviar (submit), que manda los datos al servidor. Otros, como reset, borran lo escrito.

Un formulario por sí solo no guarda nada: solo recoge y envía. Quien procesa y almacena los datos es el servidor.

Validación y procesamiento

2. Validación en el navegador

Antes de enviar, el propio formulario comprueba que los datos cumplen unos requisitos: campos obligatorios, formatos correctos (correo, fecha), números dentro de un rango...

4. Procesamiento en el servidor

  • Recepción y proceso de los datos.
  • Almacenamiento en una base de datos (registro) o uso temporal (búsqueda).
  • Respuesta: confirmación, agradecimiento, mensaje de error...

Tecnologías del servidor

Para procesar los datos existen lenguajes y plataformas como PHP, Node.js, Python (Django, Flask), Java (JSP, Spring) y .NET. Los datos se almacenan en bases de datos como MySQL o PostgreSQL.

Importante: la validación del navegador mejora la experiencia, pero no es segura: cualquiera puede saltársela. El servidor siempre debe volver a validar los datos.

Método de envío: GET o POST

GET

  • Envía los datos en la propia URL.
  • Útil para búsquedas o cuando los datos deben ser visibles o compartibles (un enlace).
  • Limitado en tamaño (las URL tienen un máximo, del orden de unos pocos miles de caracteres).

POST

  • Envía los datos en el cuerpo de la petición HTTP: no aparecen en la URL.
  • Permite enviar más información (archivos, por ejemplo).
  • Se usa en registros, inicios de sesión, compras...

POST oculta los datos de la URL, pero no los cifra. Para proteger contraseñas y datos personales hace falta HTTPS. Nunca envíes contraseñas por GET.

Etiquetar los campos: <label>

Cada campo necesita una etiqueta que diga qué hay que escribir. Un label y un input quedan unidos cuando el for del label coincide con el id del input.

Por qué importa: al hacer clic en la etiqueta, el cursor va al campo (zona de clic mayor), y los lectores de pantalla leen la etiqueta cuando el usuario llega al campo (accesibilidad).

Haz clic en las etiquetas

Sin for: Contraseña (clic aquí no hace nada)

placeholder es una pista dentro del campo; no sustituye al label (desaparece al escribir).

Opciones: radio y checkbox

  • Radio: todos los de un grupo comparten el mismo name (así solo se marca uno). El value es lo que se envía.
  • Checkbox: cada casilla es independiente. Si no está marcada, no se envía nada.

Botones y agrupación de campos

<button>

Botón de propósito general. Es similar a input type="button", pero se recomienda <button> porque puede contener texto con formato e imágenes.

Agrupan campos relacionados bajo un título, y ayudan a la accesibilidad.

Formularios adaptativos

Con @media los formularios se adaptan a la pantalla. Ejemplo típico: label e input están uno al lado del otro en pantallas anchas y uno debajo del otro en pantallas estrechas.

Resumen

Formulario

Recoge datos y los envía a un servidor con action y method.

Controles

input (muchos type), select, textarea, datalist, button, fieldset.

label y name

Cada campo lleva label for + id, y un name para que viaje el dato.

GET y POST

GET va en la URL; POST va en el cuerpo. Ninguno cifra: hace falta HTTPS.

Validación

required, minlength, pattern, min/max... y siempre también en el servidor.

CSS

Selectores de atributo, :focus, :valid/:invalid, border-box y media queries.

Autoevaluación: ¿lo tienes claro?

Contesta mentalmente y luego despliega cada pregunta.

1. ¿Qué diferencia hay entre GET y POST?

GET envía los datos en la URL (limitado y visible); POST los envía en el cuerpo de la petición (sin límite práctico y fuera de la URL). Ninguno cifra por sí mismo.

2. ¿Qué atributo hace que un dato se envíe al servidor?

name. Sin él, el campo no se envía.

3. ¿Cómo asocias un label con un input?

El for del label debe coincidir con el id del input.

4. ¿Cómo haces que varios radios sean excluyentes?

Dándoles el mismo valor en name.

5. Escribe un selector CSS que dé estilo solo a los campos de contraseña.

input[type=password] { ... }

6. ¿Por qué no basta con validar en el navegador?

Porque se puede saltar; el servidor debe volver a validar.
