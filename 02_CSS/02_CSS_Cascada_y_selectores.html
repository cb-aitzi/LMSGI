Sección 1

La cascada: ¿qué regla gana?

Qué pasa cuando dos reglas dicen cosas contrarias sobre el mismo elemento.

Cuando dos reglas se contradicen

Puede que a un mismo elemento le lleguen estilos distintos. ¿De qué color se verá «Kaixo»?

ResultadoKaixo

Rojo. Cuando las reglas se contradicen, gana la más específica. El atributo style apunta a un único elemento, así que es más específico que p, que apunta a todos los párrafos.

Escalera de prioridad: de menos a más

Cuanto más arriba en la escalera, más prioridad. Si dos reglas están al mismo nivel y se contradicen, gana la que aparece más tarde en el código.

El último gana, salvo con !important

Propiedad repetida: gana la última

!important cambia el resultado

Con !important forzamos que un valor tenga prioridad, aunque haya otro más abajo.

Úsalo lo menos posible. Cuando todo es «importante», ya nada lo es, y el CSS se vuelve muy difícil de mantener. Si necesitas !important a menudo, probablemente tus selectores están mal planteados.

Otra norma: si dos reglas vienen de dos archivos externos enlazados con <link>, tiene prioridad el último que aparece en el HTML.

Elementos anidados: el más interno manda

Muchas propiedades (como el color del texto) pasan de padres a hijos. Esto se llama herencia.

<p> · color: red Hoy el café es <strong>gratis para todos.

El <strong> está dentro del <p>. Sin regla propia heredaría el rojo; como tiene la suya, se ve azul.

Regla práctica: lo más interno y lo más específico prevalece.

Un CSS ordenado se mantiene mejor

Reglas repetidas, reglas que nunca se usan, propiedades heredadas que pasan desapercibidas... ¿cuánto tardarías en encontrar una regla entre mil líneas? La solución es organizarse:

  • Ordenar las reglas alfabéticamente: a, div, em, #primera...
  • O en el mismo orden que aparecen en el HTML: html, body, h1, h2...
  • O agrupadas por función: bordes, colores, maquetación...
  • Ordenar las propiedades dentro de la regla alfabéticamente, o de fuera hacia dentro (margin, border, padding, text-align, font-size).
  • ¡Y comentar! Un buen comentario ahorra mucho tiempo.
Sección 2

Selectores: elegir a quién se aplica cada estilo

La habilidad más importante para escribir buen CSS.

¿Qué es un selector?

Es el patrón que dice a qué elementos HTML se aplicará el estilo. Es como la dirección en un sobre: decide quién recibe el paquete.

Selectores simples

  • Universal *
  • De tipo o etiqueta p
  • De clase .alerta
  • De id #cabecera
  • De atributo [href]

Selectores jerárquicos

  • De descendiente div p
  • De hijo ul > li
  • De hermano adyacente h2 + p
  • De hermano general h2 ~ p

Otros

  • Pseudo-clases a:hover
  • Pseudo-elementos p::first-letter

Una buena selección da hojas de estilo coherentes y fáciles de mantener. Lo ideal: HTML y CSS independientes, para dar formato sin tocar el HTML. Para eso hace falta un HTML bien estructurado y dominar los selectores.

Selector universal y selector de tipo

Universal *

Selecciona todos los elementos de la página. Se usa mucho para «resetear» márgenes y rellenos.

De tipo (etiqueta)

Selecciona todos los elementos de ese tipo: p, h1, div...

Selector de clase: .nombre

Sirve para distinguir elementos del mismo tipo (por ejemplo, un párrafo de otro). En el HTML se pone class="..."; en el CSS, un punto delante del nombre. Una clase se puede repetir en muchos elementos.

Este es un mensaje de éxito.

Varias clases: class="alert grande" aplica ambas. En CSS, .alert.grande (pegadas, sin espacio) solo afecta a los elementos que tienen las dos.

Un id no se debe repetir dentro de una página. Aunque el navegador lo permita, se pierde la ventaja de identificar un elemento de forma única.

Agrupar y combinar selectores

Agrupar con comas

Aplica las mismas reglas a varios selectores a la vez.

Combinar (más precisión)

Cuidado con el espacio: p.alert (pegado) = un párrafo con clase alert. p .alert (con espacio) = elementos con clase alert dentro de un párrafo. Son cosas distintas.

Selectores de atributo

Seleccionan elementos según sus atributos HTML (href, type, class...) y, si hace falta, su valor.

SelectorSelecciona los elementos...Ejemplo
[attr]que tienen el atributo, sea cual sea su valorinput[type] { border: 1px solid black; }
[attr="valor"]cuyo atributo vale exactamente ese valorinput[type="text"] { background-color: yellow; }
[attr~="valor"]cuyo atributo es una lista de palabras y una es ese valor[title~="cafe"] { color: brown; }
[attr^="valor"]cuyo valor empieza por...[href^="https"] { color: green; }
[attr$="valor"]cuyo valor termina en...[href$=".pdf"] { color: red; }
[attr*="valor"]cuyo valor contiene...[class*="icon"] { font-size: 24px; }

Mnemotecnia: ^ es el comienzo (como en las expresiones regulares), $ el final y * «en cualquier parte».

Selectores jerárquicos: la familia del HTML

SímboloNombreEjemplo

  • Descendiente (espacio): cualquier nivel dentro del padre (hijos, nietos...).
  • Hijo (>): solo los hijos directos.
  • Adyacente (+): el hermano que va justo después.
  • General (~): todos los hermanos que van después.

Pseudo-elementos: elegir una parte de un elemento

Afectan a una parte del elemento (su primera letra, su primera línea) o crean contenido antes o después. Se escriben con dos dos puntos: ::first-letter.

Pseudo-clase o pseudo-elemento: la pseudo-clase es un estado o condición del elemento (:hover, :nth-child()). El pseudo-elemento es una parte o un contenido añadido (::before, ::first-letter).

En los materiales verás :before con un solo punto; es la sintaxis antigua. Hoy se recomienda ::before.

Si dos selectores chocan, gana el más específico

Cada selector «puntúa» según lo que contiene. Se compara columna a columna, de izquierda a derecha:

Selectoridsclases, atributos, pseudo-clasesetiquetas

p.alert011
div.success p012
#main-header100
#main-header .alert110

En orden de fuerza: id > clase / atributo / pseudo-clase > etiqueta. Un solo id vence a cualquier número de clases.

Ejemplo: con #main-header y p.alert sobre el mismo elemento, gana #main-header. Si hay empate, gana la regla que va después.

Ejercicio Ej_CSS_02: practica con selectores

El enunciado está en el Drive de la asignatura. Antes de empezar, repasa con estas preguntas:

  1. ¿Qué selector usarías para dar estilo a todos los párrafos? ¿Y solo a uno?
  2. ¿Cómo seleccionarías las celdas que están solo en el <tfoot> de una tabla? (tfoot td)
  3. ¿Qué diferencia hay entre div p y div > p?
  4. Si dos reglas se contradicen, ¿cuál gana?

Consejo: abre el navegador, pulsa F12 y mira la pestaña Elementos. Verás qué reglas CSS afectan a cada elemento y cuáles se están «tachando» porque otra gana.

Resumen

Cascada

Gana la regla más específica; con igual peso, la última. Evita !important.

Prioridad

navegador < CSS externo/interno < atributo style < !important.

Selectores simples

Etiqueta, .clase, #id, *, [atributo].

Jerárquicos

Descendiente (espacio), hijo (>), hermano adyacente (+) y general (~).

Pseudo-clases

Estado o posición: :hover, :focus, :nth-child(), :not().

Especificidad

id > clase/atributo/pseudo-clase > etiqueta.

Autoevaluación: ¿lo tienes claro?

Contesta mentalmente y luego despliega cada pregunta.

1. Un p tiene style="color:red" y el CSS dice p { color: blue }. ¿De qué color se ve?

Rojo: el atributo style tiene más prioridad.

2. ¿Qué diferencia hay entre una clase y un id?

La clase (.nombre) se puede repetir; el id (#nombre) es único en la página.

3. ¿Qué diferencia hay entre ul li y ul > li?

ul li: cualquier li dentro del ul, a cualquier nivel. ul > li: solo los hijos directos.

4. ¿Qué selecciona a[href$=".pdf"]?

Los enlaces cuyo href termina en «.pdf».

5. ¿Qué especificidad gana: #menu o div.principal p.texto?

#menu: un id vence a cualquier número de clases y etiquetas.

6. ¿En qué orden se escriben las pseudo-clases de los enlaces?

:link, :visited, :hover, :active (LoVe HAte).
